# Stream 7 — Marketplace creator + admin frontend

Status: **DONE_WITH_CONCERNS**

## Summary

Bootstrapped a Next.js 15 + App Router + TypeScript frontend under
`greybox-marketplace/web/` that talks to the existing Node `node:http`
marketplace backend through a server-side proxy. The proxy injects the admin
bearer token so it never leaves the server. Routes exactly match the existing
API contracts in `greybox-marketplace/src/api/server.ts` and the types in
`greybox-marketplace/src/types.ts`.

## Known limitations / concerns

1. **Playwright browsers not installed locally.** Spec files compile and the
   mocks are deterministic, but the four e2e suites have not been executed.
   Listed `DONE_WITH_CONCERNS` for this reason.
2. **Stripe Connect onboarding redirect is real,** but the mock e2e test
   substitutes a same-origin URL via `page.route` so the wizard can be walked
   without ever leaving Next.js. Production behavior goes through Stripe.
3. **No SSO yet.** `lib/auth.ts` reads a session cookie / proxy header but the
   identity provider is not wired up. Creator and admin pages currently look
   up the active actor from `localStorage` (creator dashboard uses
   `gb_onboarding_state.creatorId`). This is acceptable for the public beta
   per the launch plan, but should be replaced with cookie-based sessions
   before GA.
4. **Type duplication.** `web/lib/marketplace-types.ts` mirrors a slice of
   `greybox-marketplace/src/types.ts`. The path alias `@marketplace/types` is
   wired in `tsconfig.json` but unused — the backend types pull in Node-only
   modules transitively and don't survive a Next.js client compile.
   Tracked as the swap-out point for the future `@greybox/schema` package.
5. **Reject / Request-changes are local-only** until corresponding backend
   routes ship.
6. **Listing wizard file upload is staged client-side** (no backend route for
   asset multipart yet).
7. **No hardcoded API URLs.** All requests go through `/api/proxy/...`; the
   proxy reads `MARKETPLACE_API_URL` at request time (default
   `http://127.0.0.1:8181`, matching the project's `.env.example`).
