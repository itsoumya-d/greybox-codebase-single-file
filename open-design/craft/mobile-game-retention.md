# Mobile Game Retention

Use when designing mobile sessions, daily goals, idle loops, notifications, events, gacha, one-thumb player experience, and live retention systems. Mobile retention should respect fragmented attention while giving players meaningful reasons to return.

## What To Produce

- Session model: snack, commute, evening, idle check-in, or long play.
- First-day, first-week, and first-month retention plan.
- Daily and weekly goal structure.
- Notification strategy with timing, consent, and value.
- Idle/offline progress rules.
- Event calendar and burnout protections.
- Monetization fairness notes if purchases exist.

## Session Length

Design around real mobile contexts.

| Session Type | Length | Design Need |
|---|---:|---|
| Check-in | 30-90 seconds | Collect, assign, claim, quick decision |
| Snack | 2-5 minutes | One match, one run, one puzzle, one craft |
| Commute | 10-20 minutes | Several rounds, quest chain, event progress |
| Evening | 30+ minutes | Deeper build planning, social, story, ranked |
| Idle return | Variable | Offline progress summary and next action |

The same game can support multiple session types, but the UI must expose the right next action quickly.

## First Day

Day 1 should prove the fantasy and reduce uncertainty.

- First 30 seconds: one satisfying action, no account wall unless required.
- First 3 minutes: core loop completed once.
- First 10 minutes: first upgrade or collection moment.
- First session end: clear return hook.
- First day: a finite set of goals, not a giant system map.

Avoid asking for notifications, ratings, or purchases before the player has received real value.

## Daily And Weekly Goals

Goals should guide, not coerce.

Good daily goals:

- Complete any 3 missions.
- Upgrade one item.
- Help a friend or clan.
- Win or play one match.
- Harvest and replant.

Weak daily goals:

- Force a disliked mode.
- Require long sessions unexpectedly.
- Punish missed days by breaking streak value.
- Hide true completion time.

Weekly goals can ask for deeper engagement, but they need catch-up and visible progress.

## Streaks And Return Triggers

Streaks are high-risk. Use them gently.

- Prefer milestone streaks with grace days.
- Let players repair or freeze streaks through play, not only payment.
- Avoid resetting months of identity because of one missed day.
- Use return triggers based on player-authored plans: crop ready, craft done, clan event, ranked reset, new story chapter.

The healthiest return hook is "something I care about is ready," not "the game will punish me."

## Idle And Offline Progress

Idle systems need meaningful re-entry.

- Show what happened while away.
- Let the player make a decision immediately after claiming.
- Cap offline gains clearly.
- Avoid infinite accumulation that trivializes active play.
- Use helpers, buildings, expeditions, or crafting queues as readable progress sources.
- Provide low-friction collection without hiding strategic choices.

Idle play is not passive if the return choice matters.

## Notifications

Notifications must be earned and configurable.

- Ask after the player understands the value.
- Use clear categories: event, social, completed task, energy full, story.
- Avoid late-night or spammy timing.
- Do not send shame-based messages.
- Let players set quiet hours and categories.
- Make each notification deep-link to the relevant action.

A notification that opens to a confusing home screen wastes trust.

## Events And Live Ops

Events should add novelty without creating exhaustion.

- Use readable event duration and reward path.
- Include catch-up or flexible completion.
- Reuse mechanics with one strong twist, not a pile of chores.
- Separate cosmetic chase from competitive power.
- Vary intensity: major event, small event, quiet week.
- Leave production buffer for bugs, balance, and localization.

Mobile calendars often fail by stacking too many simultaneous obligations.

## Monetization Ethics

Mobile monetization needs extra care because purchases are close to habit.

- No disguised prices or confusing currency ladders.
- Show odds for randomized rewards.
- Avoid paywalls after deliberately frustrating friction.
- Separate child-safe defaults where needed.
- Keep ads optional or clearly rewarded.
- Make subscriptions and passes understandable.
- Respect spending limits and refund policies.

Design a good free experience first. Monetization should enhance commitment, expression, or convenience without degrading the base loop.

## Burnout Prevention

Retention is not maximum daily time.

- Use rest days, low-pressure events, and capped rewards.
- Avoid stacking expiring currencies.
- Let players skip modes they dislike.
- Provide auto-complete only after mastery or repetition is proven.
- Make returning after absence welcoming.
- Do not punish vacation, illness, school, work, or family life.

Burned-out players may keep logging in briefly, but they stop loving the game.

## Anti-Patterns

- First session blocked by account creation, ads, or store prompts.
- Dailies that take longer than advertised.
- Streak resets that create anxiety rather than pride.
- Notifications that use guilt or false urgency.
- Events that require perfect attendance.
- Offline progress claim screens with no follow-up decision.
- Monetization that sells relief from intentionally slow design.

## Agent Checklist

- What session lengths does this design support?
- Does Day 1 complete the core loop and create a fair return hook?
- Are dailies flexible and honest about time?
- Do notifications deliver player-valued information?
- Does idle progress create a decision on return?
- Are events paced with burnout prevention?
- Is monetization transparent and non-punitive?
