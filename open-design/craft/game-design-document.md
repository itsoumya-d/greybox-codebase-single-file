# Game Design Document

A GDD should be a production decision tool, not a lore dump or pitch sheet.

## What To Produce

- Vision, genre, target platforms, player fantasy, pillars, core loop, and target session shape.
- Mechanics, progression, economy, narrative, art direction, audio, UI/HUD, accessibility, and technical constraints.
- Production scope with team scale, milestone plan, risks, and vertical-slice cutline.

## Design Rules

- Start with the playable promise: what the player does every minute.
- Tie every mechanic to a pillar, player motivation, or production requirement.
- Separate confirmed systems from open questions.
- Use tables for tunable systems such as damage, XP, currencies, unlocks, enemy roles, and content budgets.
- Make contradictions visible, especially when narrative, economy, combat, and platform constraints compete.

## Production Gates

- Include solo/indie/AA/AAA scaling variants when the brief is oversized.
- Name asset load, engineering risk, networking risk, content volume, and QA risk.
- Add an accessibility plan before polish, not after content lock.

## Agent Checklist

- Include core loop and meta loop.
- Include scope and milestone assumptions.
- Include dependencies across disciplines.
- Include explicit next decisions for the creator.
