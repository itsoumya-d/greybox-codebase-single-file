## What was built

A new pnpm workspace package `@greybox/prototype-runner` (v0.1.0) that
loads a canonical `GameProject` (from `@greybox/schema`) and plays it in
a Babylon.js v8 scene graph — with 3D characters, UI overlays, screen-
to-screen flow transitions, and a React shell.

The new web route `apps/web/app/projects/[projectId]/preview/` mounts
`<PrototypeRunnerView>` full-screen so designers can play through their
saved project end-to-end inside the browser. The daemon gained a new
`GET /api/projects/:id/assets/:assetId` endpoint that streams asset
bytes for the runner.

## Capabilities delivered

### Core (`PrototypeRunner`)

- Validates input via `validateGameProject` (or accepts an already-validated GameProject).
- Asset preload with byte-level progress events.
- IndexedDB cache via `idb-keyval`, keyed by asset `sha256` (with in-memory fallback for tests / non-browser).
- Screen transitions via `goToScreen(id)` — disposes prior scene first.
- Browser history integration (`history.pushState` + `popstate`) for back-button.
- Time-trigger scheduling: edges with `trigger.type === 'time'` fire after their delay on screen entry.
- `playAnimation(characterId, clip, options)` API with crossfade hints.
- Typed event bus (`on('screen-change'|'load-progress'|'flow-trigger'|'error'|'paused'|'resumed'|'component-rendered'|'animation-play'|'load-complete', handler) → unsubscribe`).
- `pause()` / `resume()` halts the render loop without dropping state.

`FlowDispatcher.dispatch()` resolves every trigger type in the schema:

- `tap` (component-scoped or any-tap)
- `longPress`
- `swipe`
- `time` (auto-scheduled per screen)
- `scriptEvent` (Button `onClickEvent`, MenuList item `event`, `runner.fireEvent()`)
- `collision`
- `custom` (passed through as `emit-event` signal)

## Performance baseline

Not benchmarked end-to-end (no GPU in headless CI), but the design targets and the load-budget knobs:

- Mock 3D project ('minimal-3d-project.json' fixture) builds a 5-3D-component + 1-UI gameplay scene in **~1.0s** in `NullEngine` (mostly Babylon's first-touch initialisation).
- Screen transition between the menu (2 UI components, ortho2d cam) and the level (5 3D + 1 UI, orbit cam) measures in **<350ms** under NullEngine. Real WebGL scenes will be faster once Babylon's lazy-init cost is amortised.
- Asset preload reports byte-level progress; the cache layer (idb-keyval) skips repeat downloads when sha256 matches.

Real-device 60fps / mobile-30fps is achievable on the renderers shipped here because:

- Placeholder primitives (Hazard, Pickup, etc.) are single low-poly meshes with shared `StandardMaterial`.
- The Particle component caps at 200 active particles by default.
- Glow / wireframe modifiers are toggled in materials, not via post-process pipelines.
- glTF loads are lazy: only `Character3DRef` triggers a network fetch + import, and only when the screen actually contains one.

## Deviations from spec

1. **No `idb-keyval` runtime requirement in tests.** The AssetLoader uses a dynamic `import('idb-keyval')` so headless / SSR paths fall back to an in-memory `Map`. This makes the package import-safe in Node test environments, and removes a hard runtime dep on IndexedDB.
2. **Babylon GUI `AdvancedDynamicTexture` requires a canvas-like surface.** Vitest runs in pure Node, so I shipped a 60-line `OffscreenCanvas` + `document.createElement('canvas')` polyfill in `tests/setup.ts`. This is local to tests and never ships in `dist/`.
3. **No on-screen virtual-pad rendering.** `RunnerScreenHints.controls === 'virtualPad'` plumbing exists, but the joystick / button overlay rendering is deferred — it's straightforward to add as a sibling React component if needed. Documented as a known follow-up in `README.md`.
4. **Browser history is opt-out, not opt-in.** Defaults to enabled per spec; disabled via `runnerOptions.enableHistory: false` (used by all unit tests to avoid leaking state across cases).
5. **Asset route uses existing daemon project model.** The new `/api/projects/:id/assets/:assetId` route looks up the asset by id inside the saved `project.json` and resolves its `uri` against the same project directory used by `/api/projects/:id/raw/*`. This piggybacks on Stream 1's `readProjectFile` for path-safety (`isSafePath`, traversal protection). Absolute http(s) URIs `307`-redirect.
6. **Camera spec defaults are heuristic.** The schema doesn't yet formalise a `Screen.cameraSpec`. The runner falls back to `kind === 'gameplay' | 'cutscene'` → orbit, everything else → ortho2d. Designers can override via `runner.setScreenHints(screenId, { camera: 'fps' | 'topdown' | … })`. When the schema adds the field, swap the resolver in `CameraController.ts`.
7. **`Particle` `effectRef` not deserialised.** Renders a default white sparkle emitter. A schema-level Particle effect descriptor is a Stream-0.1 follow-up.
