## Deviations from spec

1. **`main` extension**: spec wanted `./dist/index.js`. Delivered as
   `./dist/index.js` exactly (NodeNext + `"type": "module"` makes it
   ESM with `.js`). This intentionally differs from the rest of the
   monorepo's existing packages, which use `.mjs` outputs via esbuild.
   Build is `tsc` only — simpler, no esbuild step.
2. **`@vitest/coverage-v8` not added**: see Coverage section above. The
   `test:coverage` script exists but the provider is not installed.
3. **`zod-to-json-schema` version**: spec said "add as dependency"; the
   workspace lockfile already resolves `3.25.2`. Declared as
   `^3.23.0` (compatible) so resolution stays stable across the monorepo.
4. **`emptyGameProjectScaffold()`** added as a small bonus helper for
   editors creating a new project. It returns `unknown` (the scaffold
   intentionally lacks `meta.id`) so callers must validate after filling
   in the project id. Not in the spec but matches the spirit of
   "schema is the source of truth."
5. **No `apps/daemon` consumption wired**: spec didn't ask for it. The
   daemon's `package.json` already has the structure to pull this in
   via `workspace:*` when Streams 1–7 land.

## Known gaps / TODOs for future work

- **`migrate()` is a stub.** Only same-version pass-through works.
  When `SCHEMA_VERSION` bumps past 0.1.0, write `migrate_0_1_0_to_X_Y_Z`
  helpers and wire the chain. README documents the procedure.
- **No cross-screen / cross-character reference validation.** Components
  may reference `assetRef`, `characterRef`, etc. with a string that
  passes the branded-id syntax check but doesn't actually resolve to
  any entity in the same project. A `validateProjectIntegrity(project)`
  function (separate from the per-shape validators) would catch
  dangling refs at load time. Recommended as a Stream-0.1 follow-up.
- **No cycle detection** in `validateScreenParentRefs`. Self-parent is
  caught; longer cycles (`a → b → a`) are not. Low priority — the
  editor UI prevents these in practice.
- **Component `properties` escape hatch.** Each variant has a
  `Record<string, unknown>` `properties` field. Useful while we shake
  the spec out, but consumers should treat unknown keys as best-effort.
  When a kind's `properties` content stabilises, formalise it as typed
  fields.
- **No coverage harness installed.** See Coverage section.
- **JSON Schema emission uses draft-7 (zod-to-json-schema default).**
  Unity / Unreal / Godot plugins should regenerate from
  `getJsonSchemas()` at build time rather than vendoring stale files.
