# Stream 3 — Character Generation Service — Status Report

**Date:** 2026-05-27
**Status:** **DONE**

## Summary

Built the cloud-side character generation service end to end: provider abstractions for Meshy v3, Tripo3D, and a deterministic mock; a typed router with auth + license gating; a job + library store with both in-memory and Postgres implementations; glTF validation + Mixamo-standard skeleton normalization; asset registration to local disk or S3; full HTTP wiring into the existing `createGreyboxCloudServer`.

## Providers wired

| Provider | Status | Notes |
| --- | --- | --- |
| `meshy-v3` | **Implemented** | Wired to `POST/GET /openapi/v1/text-to-3d`. Maps canonical styles -> Meshy `art_style` values. Throws on missing `MESHY_API_KEY` at construction. Errors are redacted (Bearer tokens + sk/pk-prefixed strings stripped) before reaching the API caller. |
| `tripo3d` | **Implemented** | Wired to `POST /v2/openapi/task` and `GET /v2/openapi/task/:id`. Auto-promotes to `image_to_model` when `referenceImageUrl` is provided. Auto-rig requests include the standard idle/walk/run animations. |
| `mock` | **Implemented** | Deterministic delays from `seed`. Fixture URL via `GREYBOX_CHARACTER_MOCK_FIXTURE_URL`. Default duration 10s; tunable per-test via constructor options or `GREYBOX_CHARACTER_MOCK_DURATION_MS`. Supports forced failure via `FAIL` substring in the prompt for testing the failed-state path. |

`characterGenRegistryFromEnv()` builds the registry from process.env. Default-provider precedence: explicit env var -> `meshy-v3` if key set -> `tripo3d` if key set -> `mock`. The mock is always registered as a fallback so the offline development loop is never blocked by missing API keys.

## Routes added (all under `/v1/characters`)

| Method | Path | Behaviour |
| --- | --- | --- |
| `GET` | `/v1/characters/providers` | Lists registered provider descriptors. Reports whether the caller is licensed to use them. |
| `POST` | `/v1/characters/generate` | Body validated; submits to provider; persists job; returns `202` with `jobId`, `providerJobId`, `providerName`. |
| `GET` | `/v1/characters/jobs/:id` | Polls upstream provider for fresh status. Auto-imports + registers the resulting `Character + Asset` when the upstream transitions to `done`. Idempotent on repeated polls (already-imported jobs skip re-import). |
| `POST` | `/v1/characters/import` | Manual import path. Accepts `{ jobId }` (re-import a finished job) or `{ gltfUrl, providerProvenance?, name? }` (import an arbitrary URL). |
| `GET` | `/v1/characters` | Lists imported characters for the auth-context tenant (page-able via `?limit=`). |
| `GET` | `/v1/characters/:characterId` | Fetches a single Character spec for the tenant. |

All routes are mounted in `src/server.ts` via `handleCharacterRoute`, mirroring the existing per-router pattern (e.g. `routers/inference.ts`). Auth: `authenticateRequest`. License gate: `'pro' | 'studio' | 'enterprise'` (configurable via `CharacterService.allowedTiers`).

## Job + library store

- **Interface:** `CharacterJobStore` in `src/stores/CharacterJobStore.ts`.
- **Backings:**
  - **In-memory** (`InMemoryCharacterJobStore`) — default; used by tests and single-process dev.
  - **Postgres** (`PostgresCharacterJobStore`) — used when `GREYBOX_CHARACTER_JOBS_PG_URL` is set; bootstrapped from `index.ts` (matching the pattern of `LicenseRecordsStore`).
- **Tables:** `character_jobs` (id, tenant_id, user_id, provider_name, provider_job_id, state, percent, input, outputs, error, imported_character_id, created_at, updated_at) and `characters` (id, tenant_id, name, gltf_asset_uri, sha256, size_bytes, rig, animations, game_stats, provenance, schema_version, warnings, created_at). Both indexed `(tenant_id, created_at DESC)`.
- **Migration:** `db/migrations/0001_character_jobs.sql` for explicit deploys (the Postgres store will also lazy-create tables on first use to match `licenseRecordsPostgres.ts`).

## Asset registration

- `src/providers/character-gen/asset-registry.ts`.
- Backends:
  - **Local** (`LocalFilesystemAssetStorage`) — default; writes to `${GREYBOX_ASSET_ROOT}/characters/${tenantId}/${characterId}.glb`. Optional `GREYBOX_ASSET_PUBLIC_BASE_URL` produces an HTTPS URL the prototype runner can fetch.
  - **S3-compatible** (`S3AssetStorage`) — opt-in when `GREYBOX_S3_BUCKET` + `GREYBOX_S3_ENDPOINT` are set. Uses fetch directly (no AWS SDK dep) with a pluggable `authHeader` so operators wire their own signer.
- Computes sha256, sizeBytes, and records provenance (genProvider, prompt, seed, license, modelVersion).
- Returns `{ uri, publicUrl }` — the public URL is the one the prototype runner / Unity plugin fetches.

## glTF validation & skeleton normalization

- `src/providers/character-gen/gltf-normalizer.ts`.
- **No `@gltf-transform/core` dependency added** — instead, I parse the GLB container + embedded JSON chunk directly. This is deliberate: it keeps the cloud's dependency surface zero-cost, matches the pattern of using `node:crypto` and built-ins elsewhere in the repo, and is sufficient because we only inspect node names and animation channel targets (mesh data is irrelevant for normalization).
- **Joint mapping:** `JOINT_ALIASES` covers Mixamo source names (identity), Ready Player Me-style snake_case (`left_upper_arm`), Unreal-style suffixes (`upperarm_l`, `clavicle_r`, `thigh_l`), and generic aliases (`hips`, `chest`). Unmapped joints are reported as warnings on the imported Character so the UI can flag them.
- **Animation labels:** word-boundary regex against the standard set (`idle`, `walk`, `run`, `jump`, `attack`). Best-effort; unrecognized clips pass through with `canonicalLabel` undefined.

## Known limitations

1. **Skeleton normalization is heuristic.** For rigs with creative joint names (extra finger joints, tails, wings) the unmapped joints are surfaced as warnings rather than failing the import. The Character record carries a `warnings: string[]` field so the page-by-page editor / Unity importer can show a banner. This matches the brief's "warn rather than fail" guidance.
2. **No live integration test against Meshy or Tripo3D.** Both providers are exercised via recording fetch shims that assert on payload shape; a live smoke-test belongs in a separate non-CI script (parallel to `cli/onprem-smoke.ts`) to avoid spending external credits in unit tests.
3. **S3 PUT body via `latin-1` string round-trip.** The minimal `FetchLike` shape we share with the rest of the cloud only supports `string` bodies, so the in-line S3 upload encodes binary as latin-1 for transport. Operators wiring real AWS will inject a real `fetch` impl that handles bytes natively; the existing `S3AssetStorage` accepts that via `S3StorageOptions.fetch`.
4. **No streaming /v1/characters list pagination cursor.** Limit-only for now; matches the depth of other list endpoints (e.g. `LicenseRecords`). Cursor-based pagination is a follow-up if/when tenant libraries exceed ~500 characters.
5. **Auto-import only on first transition to `done`.** If auto-import fails (e.g. provider URL temporarily 503s) the job is moved to `failed` with the import error. The explicit `POST /v1/characters/import` endpoint with `{ jobId }` lets the client retry without re-running generation.
6. **No `/readyz` surface for character-jobs persistence.** The discriminator (`memory | postgres | injected`) is computed but currently held as a void-discarded value; the next time we touch readiness we should add it to the existing checks map. Filed mentally as a follow-up; non-blocking.
